# ewanjee.com 개편 설계

- 작성일: 2026-09-27
- 상태: 승인(2026-09-27). 구현 계획은 `docs/superpowers/plans/`
- 대상 저장소: `EwanJee/PortFolioKR` (GitHub Pages, 도메인 `ewanjee.com`, `www.ewanjee.com`)
- 이 문서는 공개 저장소에 들어간다. 사내 시스템 이름, 사내 주소, 티켓 키, 사내 문서 번호는 적지 않는다. 수치의 원본 출처는 저장소 밖 비공개 근거 파일에 둔다.

### 1. 목적과 성공 기준

목적
- 개인 브랜딩과 네트워킹용 포트폴리오다. 무신사에서 한 일과, 문제를 보고 결정한 방식을 보여 준다.
- 지금 사이트의 모양(짙은 남색, 초록 강조, 큰 이름과 타이핑 문구)을 살리고 안쪽 구성과 내용을 바꾼다.

독자
- 동료 개발자, PM, 네트워킹으로 만나는 사람. 채용 담당자도 볼 수 있다.

성공 기준 (완료 판단)
- `https://ewanjee.com`과 `https://www.ewanjee.com`에서 새 사이트가 열린다. `www`는 지금처럼 `ewanjee.com`으로 넘어간다.
- 사례 7개, 개인 프로젝트 2개, 트러블슈팅 9건이 6장의 공개 규칙을 지킨 문장과 수치로 올라가 있다.
- 사이트의 모든 수치는 비공개 근거 파일의 항목과 1:1로 이어진다.
- `master`에 push하면 GitHub Actions가 설치, 검사, 빌드, 배포를 한 번에 한다. 공개 전 검사(8장)를 통과하지 못하면 배포하지 않는다.
- 데스크톱(1440px)과 모바일(390px)에서 레이아웃이 깨지지 않는다. 키보드로 모든 메뉴와 카드에 닿을 수 있고, 기기의 "동작 줄이기"를 켜면 움직임 없이 최종 상태가 보인다.
- 페이지마다 링크 공유용 미리보기 이미지가 있다.

### 2. 확정된 결정

- 주 독자는 개인 브랜딩과 네트워킹이다.
- 사이트에 사내 링크(사내 위키, 이슈 트래커, 메신저, 사내 대시보드, 사내 문서)는 넣지 않는다. 누구나 열 수 있는 공개 페이지 주소와 본인 연락처 링크는 넣는다.
- 한국어로 시작한다. 영어는 나중에 켤 수 있게 구조만 준비한다. 콘텐츠는 언어별 폴더에 두고 조회할 언어는 상수 하나로 정한다. 켤 때는 `en` 폴더, 언어 설정, `/en` 페이지를 더한다.
- 사내 수치는 반올림한 규모와 비율로만 적는다(6장).
- 만드는 방식은 Astro(정적 HTML)와 React 컴포넌트(움직이는 부분만)다. 사례 하나가 MDX 파일 하나다.
- 시각 방향은 지금 사이트의 틀을 유지한다(3장).
- 첫 화면 타이핑은 지금 사이트의 Typed.js와 같은 모양과 속도로 한다(4장).
- 무신사 사례 카드의 정지 이미지를 누르면 사례 페이지가 열리고, 윗부분에서 움직이는 화면(GIF)이나 구조 그림이 재생된다(4장). 개인 프로젝트 카드는 GitHub 저장소로 연결한다.
- 보안 취약점 건은 대상과 방식을 적지 않고 "API 보안 취약점 개선"으로만 적는다.
- 프로필 사진은 지금 사진을 그대로 쓴다.
- 배포는 개인 계정 `EwanJee` 전용 SSH 키로 한다. Pages 배포 방식을 GitHub Actions로 바꾸는 설정은 저장소 주인이 한 번 누른다. 커밋 작성자는 `EwanJee`의 GitHub 비공개 이메일이다.
- 첫 화면 문구는 사용자가 정했다: 타이핑 순환 문구(4장), 한 줄 소개와 일하는 방식 문단(6장 프로필).
- Purchase 팀 합류는 2026년 9월이다. 첫 결제 관련 사례 이름은 "클레임: 첫 결제 혜택 자격 복원"이다.

### 3. 시각 방향

지금 사이트에서 그대로 가져오는 것
- 색
  - 바탕 `#010e1b`
  - 패널과 상단 바 `#09203a`
  - 강조 초록 `#12d640`
  - 진한 초록(밑줄, 버튼) `#1c7d32`
  - 글자 흰색 `#ffffff`, 보조 글자 흰색 72% 불투명
- 첫 화면 구성: 큰 이름, 타이핑 문구, 가로 메뉴, 원형 소셜 아이콘
- 메뉴를 누르면 큰 이름이 위로 줄어들며 상단 바가 되고, 그 자리에 섹션이 열리는 흐름
- 섹션 제목 모양: 대문자 영문 라벨 + 오른쪽 초록 가는 선(예: `CAREER ———`)
- 팀 필터 버튼 모양: 진한 초록 테두리, 선택되면 진한 초록 바탕

바꾸는 것
- 한글 본문 글꼴은 Pretendard, 영문 제목과 메뉴는 Poppins를 쓴다.
- 본문은 왼쪽 정렬, 16px 이상, 한 줄 약 40자 안팎으로 제한한다. 지금 사이트의 가운데 정렬 목록은 없앤다.
- 메뉴는 10개에서 6개로 줄인다: Home, About, Career, Projects, Troubleshooting, Contact.
- 팀마다 색 점을 둔다. Global `#5dade2`, Retention `#f5b041`, Purchase `#c39bd3`, 그 밖(인턴·학력) 흰색 45%. 경력, 프로젝트, 트러블슈팅에서 같은 색을 쓴다. 강조 초록 `#12d640`은 팀 색으로 쓰지 않는다.
- 다크 한 가지 테마만 둔다(지금 사이트와 같다).

### 4. 애니메이션

원칙
- 움직임은 0.2~0.8초로 짧게 한다. 같은 요소는 한 번만 재생하고, 누르거나 올렸을 때 반응한다.
- `transform`과 `opacity`만 움직인다.
- 애니메이션은 꾸밈일 뿐이다. HTML에는 처음부터 최종 값을 넣어 두고 스크립트는 움직임만 더한다. 스크립트가 없거나 중간에 멈춰도 최종 값이 보여야 한다.
- 기기에서 "동작 줄이기"를 켜면 모든 움직임을 끄고 아래 고정 상태를 보여 준다.
  - 첫 화면 타이핑: "I am a Product Engineer"를 고정해서 보여 준다. 순환과 커서 깜빡임은 하지 않는다.
  - 반복하는 구조 그림(목록 카드): 결과가 드러난 마지막 장면을 정지 화면으로 보여 준다.
  - 단계 재생 그림(사례 페이지): 버튼을 누를 때만 다음 단계로 바로 바뀐다. 전환 효과는 없다.
  - GIF: 자동 재생하지 않고 정지 이미지와 재생 버튼을 보여 준다.
  - 카드에 마우스를 올려도 떠오르거나 화면이 넘어가지 않고 테두리 색만 바뀐다.
  - 숫자는 처음부터 최종 값으로 보인다.

첫 화면 타이핑
- 모양: 흰색 앞말, 초록 `#12d640` 글자, 글자 아래 `#1c7d32` 2px 밑줄(아래 여백 6px), 흰색 커서 `|`. 글자 크기 24px(모바일 20px). 지금 사이트와 같다.
- 속도: Typed.js 설정과 같다. 입력과 삭제 모두 글자당 65ms에 0~32ms를 무작위로 더한다. 입력을 마치면 0.7초 쉬고 지운다. 입력하거나 지우는 동안 커서는 멈춰 있고, 쉬는 동안 0.7초 간격으로 깜빡인다.
- 순서
  1. 앞말 "I will be A "가 먼저 보이고, 초록 글자 "Server Developer"를 입력한다(지금 사이트와 같은 첫인상).
  2. 1.5초 쉰 뒤 초록 글자를 지우고, 앞말을 "I "까지 지우고, "am "을 입력한다.
  3. 이후 초록 글자로 입력하고 지우기를 반복한다: "a Product Engineer", "a Backend Developer", "building order & claim systems", "tracing incidents to the root". 첫 문구는 "I am a Product Engineer"가 된다.
- 순환 문구는 콘텐츠 파일에서 고칠 수 있게 둔다.

메뉴 이동과 섹션
- 첫 화면에서 다른 메뉴로 가면 큰 이름이 줄어들며 상단 바의 이름 자리로 옮겨 간다. 브라우저의 View Transitions로 구현하고, 지원하지 않는 브라우저는 그냥 페이지를 바꾼다.
- 섹션 내용은 아래 10~14px에서 올라오며 나타난다(0.35초, 한 번).
- 섹션 라벨 옆 초록 선이 왼쪽에서 그려진다.
- 메뉴에 마우스를 올리면 초록 밑줄이 왼쪽에서 그어진다.

경력
- 세로선이 위에서 아래로 그려진다(0.8초). 줄은 0.15초 간격으로 차례로 나타난다.
- 숫자는 처음 보일 때 0에서 최종 값까지 올라간다(0.7초). 경과 시간은 실제 시계(`performance.now()`)로 재고, 끝나는 시점에 최종 값을 한 번 더 넣는다.

프로젝트
- 카드가 0.1초 간격으로 나타난다.
- 카드에 마우스를 올리면 5px 떠오르고 테두리가 진한 초록이 된다. 휴대폰 틀 안의 화면은 천천히(2.8초) 아래로 넘어간다. 이미지 오른쪽 아래에 "눌러서 자세히"가 나타난다.
- 팀 필터를 누르면 다른 팀 카드가 흐려진다(0.3초).
- 무신사 사례 카드의 이미지를 누르면 사례 페이지로 이동한다. 카드 이미지가 커지면서 사례 페이지 윗부분의 미디어 자리로 옮겨 가고(View Transitions), 거기서 움직이는 화면(GIF)이 자동으로 반복 재생된다. GIF는 사례 페이지에서만 불러와서 목록 화면은 가볍게 유지한다.
- 구조 그림 카드는 목록에서도 짧은 반복 애니메이션을 보여 준다. 사례 페이지에서는 재생 버튼으로 한 단계씩 넘겨 본다.
- 개인 프로젝트 카드는 이미지 없는 글자 카드(이름, 한 줄 설명, 기술 태그)다. 누르면 GitHub 저장소가 새 탭으로 열리고, 마우스를 올리면 "GitHub에서 보기"가 나타난다. 사례 페이지와 GIF는 없다.

소셜 아이콘
- 마우스를 올리면 진한 초록 바탕으로 바뀌고 2px 떠오른다.

### 5. 사이트 구조

주소와 페이지
- `/` 첫 화면: 이름, 타이핑 문구, 한 줄 소개, 메뉴, 소셜 아이콘, 일하는 방식 문단(왼쪽에 초록 선). 문구는 6장 프로필을 따른다.
- `/about` 소개: 프로필 사진, 소개 문단, 기술, 학력과 자격, 기술 블로그
- `/career` 경력 타임라인
- `/projects` 사례 목록(팀 필터: 전체, Global, Retention, Purchase, 개인)
- `/projects/<사례>` 사례 페이지 7개
- `/troubleshooting` 트러블슈팅 목록. 항목마다 고유 앵커(`#<항목>`)가 있어 링크로 공유할 수 있다.
- `/contact` 연락처
- `404` 페이지: 같은 틀에 첫 화면으로 돌아가는 링크

사례 페이지 구성
- 윗부분(세부 보기): 왼쪽에 움직이는 화면(GIF) 또는 구조 그림, 오른쪽에 팀, 상태, 제목, 기간과 역할, 핵심 칸 최대 3개, 요약 두세 문장
  - 핵심 칸에는 수치가 있으면 수치를, 없으면 짧은 사실(예: "아웃박스 + Kafka", "상태 머신 5단계")을 같은 모양으로 넣는다.
  - 핵심 칸이 0~2개여도 레이아웃이 깨지지 않게 한다.
- 본문: 문제, 검토한 대안, 결정, 결과, 배운 점. 본문 안에 조작하거나 재생하는 그림을 하나 둔다.
- 아래: 쓴 기술 태그, 이전·다음 사례

예전 주소 처리
- 첫 화면 스크립트가 예전 해시 주소를 새 주소로 넘긴다: `#about`, `#education`, `#skills` → `/about`, `#experience`, `#roadmap` → `/career`, `#portfolio` → `/projects`, `#contacts` → `/contact`.
- 예전 프레디저 상세 페이지 `projects/twitteranalysis.html`은 `/career`로 넘기는 작은 페이지로 바꾼다.
- 템플릿 원작자의 프로젝트 페이지 8개(`blog`, `gan`, `iras`, `ml`, `musicplayer`, `recommender`, `resume`, `todo`)와 `vdg`는 지운다.

### 8. 빌드와 배포

저장소와 권한
- 새 사이트는 `renewal` 브랜치에서 만든다. 완성되면 `master`에 합친다.
- 이 맥에 `EwanJee` 전용 SSH 키를 만들고, `~/.ssh/config`에 별칭(`github-ewanjee`)을 둔다. 이 저장소의 원격 주소만 그 별칭을 쓴다. 공개키는 `EwanJee` 계정 설정에 사용자가 등록한다.

패키지 설치
- 이 맥은 회사 네트워크의 npm 미러를 거쳐 설치한다. 공개 npm보다 버전이 늦을 수 있어서 미러에 있는 버전으로 고정한다.
- lockfile에 미러 주소가 남지 않게 한다(npm의 `omit-lockfile-registry-resolved` 설정 또는 이에 준하는 방법). GitHub Actions는 같은 lockfile로 공개 npm에서 설치한다.

GitHub Actions 워크플로(`master` push마다)
1. 체크아웃, Node 설치(버전은 `.nvmrc`로 고정)
2. `npm ci`
3. 공개 전 검사: 원본(콘텐츠, lockfile)
4. `astro build`
5. 공개 전 검사: 빌드 결과(`dist`)
6. Pages 아티팩트 업로드, 배포

공개 전 검사(`scripts/leak-check`)
- 공개 저장소에 둘 수 있는 일반 규칙만 스크립트에 넣는다: 사내 협업 도구 주소 형태, 티켓 키 형태의 문자열(허용 목록 예외), 전화번호와 생년월일 형태.
- 사내 도메인과 사내 시스템 이름 목록은 공개하면 안 되므로 스크립트에 쓰지 않는다. GitHub Actions 비밀값과 로컬의 추적하지 않는 파일에서 읽는다.
- 하나라도 걸리면 실패로 끝나고 배포하지 않는다.

근거 확인(로컬 전용)
- 콘텐츠의 모든 `metrics[].evidence`가 비공개 근거 파일에 있는지 확인하는 스크립트를 로컬에서 돌린다. 근거 파일은 저장소 밖에 있어서 CI에서는 건너뛴다.

끊김 없는 전환 순서 (배포 전환은 사이트 개편과 독립이라 구현 계획에서 먼저 끝내는 별도 갈래로 나눌 수 있다)
1. `master`에 지금 사이트 파일을 그대로 배포하는 워크플로를 먼저 넣는다.
2. 사용자가 Pages 배포 방식을 GitHub Actions로 바꾼다. 바꾼 직후 Pages 설정에서 사용자 도메인 `ewanjee.com`과 HTTPS 강제가 그대로인지 API로 확인한다.
3. `renewal`을 `master`에 합친다. 워크플로가 새 사이트를 배포한다.
4. 문제가 생기면 합친 커밋을 되돌려 지금 사이트를 다시 배포한다.
