title: 데이터 계약 오류 7건
team: global
summary: "지표 오류를 설계가 가정한 데이터 계약과 실제 데이터의 불일치 문제로 보고, 설계 문서를 v0.1부터 v0.6까지 고칠 때마다 실제 데이터로 다시 검사해 배포 전에 계약 8개 중 7개를 고쳤습니다."
symptom: "설계한 지표를 일본 데이터에 돌려 보니 가입 후 7일 안 첫 구매율이 82~88%로 비현실적으로 높게 나왔고, 1회 구매자 약 49만 명이 잘못 분류됐습니다."
definition: "설계 단계부터, 문서가 가정한 데이터 계약(어떤 컬럼·필터 조건·사용자 키·구매자 분류 규칙을 쓰는지)이 실제 데이터와 맞는지 검증하는 문제로 정의했습니다."
approach: "설계 문서(LLD, 구현 수준 설계)를 v0.1부터 v0.6까지 6번 고칠 때마다 실제 데이터로 스모크 테스트(설계대로 빠르게 돌려 보는 검사)를 돌렸고, 1차와 2차 검사에서 불일치를 찾았습니다. 검사는 AI 세션에서 실제 테이블 구조와 값을 직접 조회해 설계와 대조하는 방식이었습니다."
cause: "검사에서 국가 구분 값 누락, 주문 상태 필터 오류, 사용자 식별 키 오류, 구매자 분류 규칙 오류, 7일 지표 분모의 편향 등이 나왔고, 데이터 계약 8개 중 7개가 실제 데이터와 맞지 않았습니다. 82~88%는 분모가 전체 가입자가 아닌 다른 기준으로 잡혀 부푼 값이었고(자기 선택 편향, 분모가 전체를 대표하지 못하는 편향), 약 49만 명 오분류는 구매자 분류 규칙 오류 때문이었습니다."
fix: "분모를 전체 가입자 기준으로 바로잡고 구매자 분류 규칙을 고치는 등 불일치 7개를 모두 고쳤습니다."
verification: "프로토타입을 v1부터 v5까지 고쳐 운영에 적재할 때까지, 이미 고친 오류가 다시 생긴 회귀는 0건이었습니다."
prevention: "계산 결과 하나를 그대로 믿지 않고, 별도 AI 검토 도구로 보정값·예측 모델·계산식을 교차 검증하는 절차를 상시로 둡니다."
record: "실제 데이터와 맞춘 계약을 설계 문서(LLD) v0.1~v0.6에 차례로 반영했고, 검사에서 찾은 결함과 회귀 0건은 2주 단위 자체 회고에 기록했습니다. 이 작업이 속한 성장 지표 분석 프로젝트는 Jira 이니셔티브 1건으로 관리돼 출시 완료까지 추적됐습니다."
