---
title: API Gateway 전환 중 스케일아웃 502 약 800건
team: retention
summary: "파드가 늘어날 때마다 난 502를 '새 파드가 준비를 마치기 전에 요청을 받는 문제'로 정의하고, 앱이 실제로 준비된 뒤에만 요청을 받도록 준비 확인 시점을 늦춰 막았습니다."
symptom: "트래픽을 API Gateway로 70%까지 옮기던 중 파드가 늘어날 때마다 502(게이트웨이가 뒤쪽 서버에서 정상 응답을 받지 못했다는 오류)가 났고, 모두 약 800건이었습니다."
definition: "502가 파드가 늘어날 때만 났다는 점에서, 문제를 새 파드가 요청을 받을 준비를 마치기 전에 트래픽이 들어오는 준비 시점 문제로 좁혔습니다."
cause: "기존 설정에서는 파드가 약 15초 만에 Ready(요청을 받을 수 있다고 표시되는 상태)가 됐지만, 그때 앱은 아직 요청을 처리할 준비를 마치지 못한 상태였습니다."
fix: "앱의 준비 확인(readiness probe)을 15초에서 30초로 늦추고 nginx 준비 확인을 35초에 새로 둬서, 파드가 Ready가 되는 시점을 약 15초에서 약 35초로 늦췄습니다. 메모리는 2.0GiB에서 3.6GiB로 맞췄고, Kubernetes 설정 변경은 ADR(설계 결정 기록)로 합의해 반영했습니다."
prevention: "이제 파드는 앱이 실제로 준비된 뒤에만 트래픽을 받습니다. 그 뒤 공개 API 23개를 7일 만에 100% 전환했고, 100% 구간 약 1,600만 요청 중 서버 오류는 1건이었습니다."
evidence: [E-gw-502, E-gw-transition]
order: 1
