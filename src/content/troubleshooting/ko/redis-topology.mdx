---
title: Redis master를 놓친 연결
team: retention
summary: "새로 뜬 파드 2개에만 몰린 Redis 쓰기 오류를 '클라이언트가 master를 잃은 채 고정돼 재시작해야만 회복되는 문제'로 정의하고, 로컬 재현으로 원인을 확인한 뒤 연결이 스스로 복구되는 방법을 만들었습니다."
symptom: "이벤트 응모 요청 일부가 서버 오류로 실패해 모니터링 알림이 울렸고, 오류는 오토스케일로 새로 뜬 파드 2개에만 몰렸습니다(쓰기 오류 약 100건)."
definition: "Redis 서버는 정상인데 오류가 특정 파드에만 몰렸으므로, 서버 장애가 아니라 그 파드의 Redis 클라이언트가 master를 잃은 상태로 고정된 문제로 정의했습니다. 목표는 파드를 다시 띄우지 않아도 연결이 스스로 회복하게 만드는 것이었습니다."
cause: "로컬 Redis로 장애를 여러 시나리오로 재현해 운영에서 본 현상과 대조했습니다. Lettuce(자바 Redis 클라이언트)는 구성을 다시 읽는 순간 master에 닿지 못하면 master를 노드 목록에서 영구히 빼 버렸고, 그 뒤로 master에만 써야 하는 분산 락 요청이 계속 실패했습니다."
fix: "master가 돌아온 뒤에도 기존 연결을 검사하거나 재설정하는 방법으로는 회복되지 않았고, 연결 팩토리(연결을 만드는 객체)를 새로 만들 때만 바로 회복됐습니다. 그래서 오류를 감지하면 연결을 새로 만드는 자가 복구를 만들어 검증했습니다. 여러 요청이 동시에 오류를 봐도 연결은 한 번만 다시 만들고, 재시도 간격은 점점 늘립니다."
prevention: "장애 당시에는 문제 파드 2개를 직접 지워서야 복구됐습니다. 자가 복구는 사람이 파드를 다시 띄우지 않아도 연결이 스스로 돌아오게 합니다."
evidence: [E-redis]
order: 2
